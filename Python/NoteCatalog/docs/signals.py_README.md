# 📡 signals.py - Детальное объяснение

## 🎯 Что это за файл?
`signals.py` - это файл, который содержит сигналы Django. Сигналы - это механизм, который позволяет выполнять код автоматически при определённых событиях (например, при создании или сохранении объекта).

## 📋 Импорты

```python
from django.db.models.signals import post_save
from django.dispatch import receiver
from .models import Note, Tag
```

### 🔍 Объяснение импортов:

**`from django.db.models.signals import post_save`**
- `django.db.models.signals` - модуль с сигналами Django
- `post_save` - сигнал, который срабатывает после сохранения объекта
- **Зачем**: Чтобы выполнить код после создания/обновления заметки

**`from django.dispatch import receiver`**
- `django.dispatch` - модуль для работы с сигналами
- `receiver` - декоратор для создания обработчика сигнала
- **Зачем**: Чтобы создать функцию, которая будет обрабатывать сигнал

**`from .models import Note, Tag`**
- Импорт моделей Note и Tag
- **Зачем**: Чтобы работать с этими моделями в сигнале

## 🔧 Функция add_untagged_tag

```python
@receiver(post_save, sender=Note)
def add_untagged_tag(sender, instance, created, **kwargs):
    """
    Автоматически добавляет тег 'untagged' к заметкам без тегов.
    """
    if created and not instance.tags.exists():
        untagged_tag, created = Tag.objects.get_or_create(
            name='untagged',
            defaults={'slug': 'untagged'}
        )
        instance.tags.add(untagged_tag)
```

### 🔍 Детальное объяснение:

**`@receiver(post_save, sender=Note)`**
- `@` - синтаксис декоратора
- `receiver` - декоратор для создания обработчика сигнала
- `post_save` - сигнал, который срабатывает после сохранения
- `sender=Note` - сигнал срабатывает только для модели Note
- **Что происходит**: Функция будет вызвана каждый раз, когда сохраняется объект Note

**`def add_untagged_tag(sender, instance, created, **kwargs):`**
- `def` - создание функции
- `add_untagged_tag` - название функции
- `sender` - модель, которая отправила сигнал (Note)
- `instance` - конкретный объект, который был сохранён
- `created` - булево значение (True если объект создан, False если обновлён)
- `**kwargs` - дополнительные аргументы
- **Что происходит**: Функция получает информацию о сохранённом объекте

**`if created and not instance.tags.exists():`**
- `if created` - проверяем, что объект был создан (не обновлён)
- `and` - логический оператор И
- `not instance.tags.exists()` - проверяем, что у заметки нет тегов
- `instance.tags` - доступ к связанным тегам
- `exists()` - проверяет, есть ли связанные объекты
- **Что происходит**: Выполняем код только при создании заметки без тегов

**`untagged_tag, created = Tag.objects.get_or_create(...)`**
- `Tag.objects.get_or_create()` - получить объект или создать, если не существует
- `untagged_tag` - переменная для хранения тега
- `created` - булево значение (True если тег был создан)
- **Что происходит**: Ищем тег 'untagged', если не найден - создаём

**`name='untagged'`**
- `name` - поле модели Tag
- `'untagged'` - значение поля
- **Что происходит**: Ищем тег с названием 'untagged'

**`defaults={'slug': 'untagged'}`**
- `defaults` - значения по умолчанию при создании
- `{'slug': 'untagged'}` - словарь с полями для создания
- **Что происходит**: Если тег не найден, создаём его с slug='untagged'

**`instance.tags.add(untagged_tag)`**
- `instance.tags` - доступ к связанным тегам
- `add()` - метод для добавления связи
- `untagged_tag` - тег, который добавляем
- **Что происходит**: Добавляем тег 'untagged' к заметке

## 🔄 Как это работает пошагово:

1. **Пользователь** создаёт новую заметку
2. **Django** сохраняет заметку в базу данных
3. **Django** отправляет сигнал `post_save`
4. **Функция `add_untagged_tag`** получает сигнал
5. **Функция проверяет**: создана ли заметка и есть ли у неё теги
6. **Если тегов нет**: ищет тег 'untagged'
7. **Если тег не найден**: создаёт тег 'untagged'
8. **Добавляет тег** к заметке

## 🎯 Пример работы:

### Сценарий 1: Создание заметки с тегами
```python
note = Note.objects.create(
    title="Заметка с тегами",
    body="Содержимое"
)
note.tags.add(python_tag, django_tag)
# Сигнал сработает, но тег 'untagged' не добавится (уже есть теги)
```

### Сценарий 2: Создание заметки без тегов
```python
note = Note.objects.create(
    title="Заметка без тегов",
    body="Содержимое"
)
# Сигнал сработает и автоматически добавит тег 'untagged'
```

### Сценарий 3: Обновление заметки
```python
note.title = "Новый заголовок"
note.save()
# Сигнал сработает, но тег 'untagged' не добавится (created=False)
```

## 🔧 Дополнительные возможности сигналов:

### 1. Сигнал pre_save (перед сохранением)
```python
@receiver(pre_save, sender=Note)
def update_updated_at(sender, instance, **kwargs):
    instance.updated_at = timezone.now()
```

### 2. Сигнал post_delete (после удаления)
```python
@receiver(post_delete, sender=Note)
def cleanup_orphaned_tags(sender, instance, **kwargs):
    # Удалить теги, которые больше не используются
    pass
```

```python
@receiver(m2m_changed, sender=Note.tags.through)
def update_tag_count(sender, instance, action, **kwargs):
    if action == 'post_add':
        # Обновить счётчик тегов
        pass
```

## 🔑 Ключевые понятия:

1. **Сигнал** - событие в Django
2. **post_save** - сигнал после сохранения
3. **pre_save** - сигнал перед сохранением
4. **post_delete** - сигнал после удаления
5. **@receiver** - декоратор для обработчика сигнала
6. **sender** - модель, отправившая сигнал
7. **instance** - объект, с которым произошло событие
8. **created** - флаг создания объекта
9. **get_or_create** - получить или создать объект
10. **exists()** - проверить существование связанных объектов
11. **add()** - добавить связь Many-to-Many

## 🎯 Зачем нужны сигналы:

1. **Автоматизация** - выполнение кода без явного вызова
2. **Целостность данных** - поддержание консистентности
3. **Логирование** - запись событий
4. **Кэширование** - обновление кэша при изменении данных
5. **Уведомления** - отправка email, SMS и т.д.

## 🎯 Итог:

Сигналы Django - это мощный механизм для автоматизации:
- **Срабатывают автоматически** при определённых событиях
- **Позволяют выполнять код** без изменения основного кода
- **Обеспечивают целостность данных** и автоматизацию процессов
- **Упрощают поддержку** приложения

В нашем случае сигнал автоматически добавляет тег 'untagged' к заметкам без тегов! 🏷️
