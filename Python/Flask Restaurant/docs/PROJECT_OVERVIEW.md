# Обзор проекта Flask Restaurant API

## Введение

Этот документ предоставляет полный обзор проекта **Flask Restaurant API** - веб-сервиса для управления меню ресторана и информацией о поварах. Проект построен с использованием современных технологий и следует лучшим практикам разработки.

## Цель проекта

Создать REST API для управления ресторанным меню, который позволяет:
- Управлять блюдами меню (CRUD операции)
- Управлять информацией о поварах (CRUD операции)
- Фильтровать и искать данные
- Сортировать результаты
- Использовать пагинацию
- Валидировать входящие данные
- Обрабатывать ошибки

## Технологический стек

## Архитектура приложения

### Слоистая архитектура
```
┌─────────────────────────────────────┐
│           API Layer                 │  ← HTTP запросы/ответы
│        (app/api/)                   │
├─────────────────────────────────────┤
│         Service Layer               │  ← Бизнес-логика
│       (app/services/)               │
├─────────────────────────────────────┤
│       Repository Layer              │  ← Доступ к данным
│      (app/repositories/)            │
├─────────────────────────────────────┤
│         Model Layer                 │  ← Структура данных
│        (app/models/)                │
└─────────────────────────────────────┘
```

### Принципы архитектуры
1. **Разделение ответственности** - каждый слой имеет свою задачу
2. **Инверсия зависимостей** - высокоуровневые модули не зависят от низкоуровневых
3. **Единая ответственность** - каждый класс решает одну задачу
4. **Открытость/закрытость** - открыт для расширения, закрыт для модификации

## Основные компоненты

### 1. Модели данных
- **MenuItem** - блюда меню с полями: название, описание, цена, категория, доступность
- **Chef** - повара с полями: имя, специализация, дата найма, биография

### 2. API Endpoints
- **GET /api/v1/menus/** - список блюд с фильтрацией и пагинацией
- **POST /api/v1/menus/** - создание нового блюда
- **GET /api/v1/menus/{id}** - получение блюда по ID
- **PUT /api/v1/menus/{id}** - полное обновление блюда
- **PATCH /api/v1/menus/{id}** - частичное обновление блюда
- **DELETE /api/v1/menus/{id}** - удаление блюда
- Аналогичные endpoints для поваров

### 3. Валидация данных
- **Pydantic схемы** для валидации входящих данных
- **Автоматическая валидация** типов и ограничений
- **Кастомные валидаторы** для бизнес-правил

### 4. Обработка ошибок
- **Стандартизированные ответы** с кодами ошибок
- **Глобальные обработчики** для разных типов ошибок
- **Подробные сообщения** об ошибках для разработчиков
