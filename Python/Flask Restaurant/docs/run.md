# run.py - Точка входа в приложение

## Описание файла

Файл `run.py` - это **точка входа** в наше Flask приложение. Это файл, который запускается первым, когда мы хотим запустить наш веб-сервер. Представьте его как "кнопку запуска" для всего приложения.

## Что такое точка входа?

Точка входа - это файл, который выполняется первым при запуске программы. В нашем случае это `run.py`. Когда мы пишем `python run.py` в командной строке, Python начинает выполнение именно с этого файла.

## Подробный разбор кода

```python
"""Точка входа для запуска приложения."""

import os
from dotenv import load_dotenv

# Загружаем переменные окружения из .env файла
load_dotenv()

from app import create_app

app = create_app()

if __name__ == '__main__':
    app.run(debug=True, host='0.0.0.0', port=5000)
```

### Строка 1: Документация
```python
"""Точка входа для запуска приложения."""
```
- **Тройные кавычки** - это строка документации (docstring)
- **Docstring** - описание того, что делает файл
- **Зачем нужно**: Помогает другим разработчикам понять назначение файла

### Строки 3-4: Импорты
```python
import os
from dotenv import load_dotenv
```

**`import os`**
- **os** - встроенная библиотека Python для работы с операционной системой
- **Что делает**: Позволяет работать с файлами, папками, переменными окружения
- **В нашем проекте**: Используется для получения переменных окружения

**`from dotenv import load_dotenv`**
- **dotenv** - библиотека для работы с .env файлами
- **load_dotenv()** - функция для загрузки переменных из .env файла
- **.env файл** - файл с настройками (пароли, URL базы данных)
- **Зачем нужно**: Безопасно хранить секретные данные отдельно от кода

### Строка 6: Загрузка переменных окружения
```python
load_dotenv()
```
- **Вызывает функцию** load_dotenv()
- **Что происходит**: Читает файл .env и загружает все переменные в память
- **Пример .env файла**:
  ```
  DATABASE_URL=sqlite:///app.db
  SECRET_KEY=my-secret-key
  DEBUG=True
  ```

### Строка 8: Импорт функции создания приложения
```python
from app import create_app
```
- **app** - папка с нашим приложением
- **create_app** - функция, которая создает и настраивает Flask приложение
- **Зачем отдельная функция**: Позволяет создавать приложение с разными настройками (для тестов, продакшена)

### Строка 10: Создание приложения
```python
app = create_app()
```
- **Вызывает функцию** create_app()
- **Результат**: Получаем готовое Flask приложение со всеми настройками
- **app** - это объект Flask приложения

### Строки 12-13: Запуск сервера
```python
if __name__ == '__main__':
    app.run(debug=True, host='0.0.0.0', port=5000)
```

**`if __name__ == '__main__':`**
- **Специальная проверка** Python
- **Что означает**: "Если этот файл запускается напрямую, а не импортируется"
- **Зачем нужно**: Позволяет использовать файл и как модуль, и как скрипт

**`app.run(debug=True, host='0.0.0.0', port=5000)`**
- **app.run()** - запускает веб-сервер Flask
- **debug=True** - включает режим отладки
  - Автоматическая перезагрузка при изменении кода
  - Подробные сообщения об ошибках
  - Интерактивный отладчик
- **host='0.0.0.0'** - сервер доступен со всех IP адресов
  - '127.0.0.1' - только с локального компьютера
  - '0.0.0.0' - с любого компьютера в сети
- **port=5000** - порт, на котором работает сервер
  - Порт - это "дверь" для подключения к серверу
  - 5000 - стандартный порт для Flask

## Как запустить приложение

### Командная строка
```bash
# Перейти в папку проекта
cd "C:\Rep\Step\Python\Flask Restaurant"

# Запустить приложение
python run.py
```

### Что происходит при запуске
1. Загружаются переменные окружения из .env
2. Создается Flask приложение с настройками
3. Запускается веб-сервер на порту 5000
4. В консоли появляется сообщение:
   ```
   * Running on all addresses (0.0.0.0)
   * Running on http://127.0.0.1:5000
   * Running on http://192.168.0.100:5000
   ```

### Как проверить, что работает
Откройте браузер и перейдите по адресу:
- `http://localhost:5000/health` - проверка здоровья API
- `http://localhost:5000/api/v1/menus/` - список блюд
- `http://localhost:5000/api/v1/chefs/` - список поваров

## Режим отладки (debug=True)

### Преимущества
- **Автоперезагрузка**: При изменении кода сервер перезапускается автоматически
- **Подробные ошибки**: Показывает точное место ошибки в коде
- **Интерактивный отладчик**: Можно исследовать переменные при ошибке

### Недостатки
- **Медленнее**: Режим отладки работает медленнее обычного
- **Небезопасно**: Показывает внутреннюю информацию об ошибках

### Когда использовать
- **Разработка**: Всегда включать при разработке
- **Продакшен**: Никогда не включать в продакшене

## Альтернативные способы запуска

### Через Flask CLI
```bash
# Установить переменную окружения
set FLASK_APP=run.py

# Запустить
flask run --debug --host=0.0.0.0 --port=5000
```

### Через Gunicorn (продакшен)
```bash
gunicorn -w 4 -b 0.0.0.0:5000 run:app
```

## Структура запуска

```
run.py
    ↓
load_dotenv() - загружает .env
    ↓
create_app() - создает Flask приложение
    ↓
app.run() - запускает веб-сервер
    ↓
Сервер работает на http://localhost:5000
```

## Обработка ошибок

Если при запуске возникают ошибки:

1. **ModuleNotFoundError**: Не установлены зависимости
   ```bash
   pip install -r requirements.txt
   ```

2. **Port already in use**: Порт 5000 занят
   ```python
   app.run(port=5001)  # Использовать другой порт
   ```

3. **Database errors**: Проблемы с базой данных
   ```bash
   alembic upgrade head  # Применить миграции
   ```
